# Worker methods

The native launch brief owns role, scope, transport, and task policy. This
BB-owned skill grants no captain authority. Do not delegate, spawn reviewers,
change the exact selected provider/model/effort, merge, deploy, or write outside
the assigned scope. Keep the recorded worktree and exact-ID steering procedure.
Report scope gaps to the captain rather than expanding the assignment.

Read only the reference for the current task trigger:

| Trigger | Reference |
|---|---|
| Consequential behavior change; shared state, retry, or migration | [Behavioral proof](references/proof.md) |
| Changed UI journey; assigned verification-skill upkeep or creation | [Product verification](references/product-verification.md) |
| Multi-stage work changes direction or makes a consequential decision | [Decision trail](references/decision-trail.md) |
| Assigned investigation, unresolved design, or bounded review | [Research, design, and review](references/research-design-review.md) |

Return the assigned revision, result, observed verification, evidence pointers,
and uncovered requirements. Missing evidence is a gap. Worker completion is a
handoff, not captain merge or deployment completion. Use the brief's existing
result channel. Do not execute raw pstack skills or load their whole corpus.
